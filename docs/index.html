问题知道 ≠ 可执行知识库可以长期保存很多能力，但当前任务只应使用状态、规则和授权允许的那部分。
方法先编译，再规划GSC 先生成当前任务的 admissible Provider–Action 域，再让 planner 搜索。
最终外部验证E6b PASS12/12 Full 与 12/12 GSC 均 solved；0 solvability regression；12/12 GSC plans 通过 VAL。

最重要的结论

GSC 的核心证据已经闭环：它可以把 mission-conditioned domain admission 做成显式、可审计、版本绑定的治理对象，并在独立 public semantics、独立实现的 cross-implementation oracle、Fast Downward 26.6 和 VAL 下保持可解性与计划有效性。

同时，E6b 没有产生成熟 planner 的搜索加速：Fast Downward 会自行在 translation/relevance preprocessing 阶段消除同类无关结构，因此 Full 与 GSC 在 12/12 holdout 上成为相同的有效搜索问题。这不是 gate failure，而是计算收益的边界条件。

论文应该怎样表述主张？

Primary claim
GSC 是显式、可审计、mission-conditioned 的 domain-admission boundary；E6b 验证其在外部 native semantics + independent planner/validator 下保持 soundness 与 solvability。
Secondary claim
当 mission-irrelevant / governance-invalid alternatives 会存活到 planner 的有效 search representation 时，semantic admission 可以减少 search pollution。
Do not claim
不要写成“GSC 普遍加速规划器”或“对成熟 planner 必然缩小 search space”。E6b 已给出明确反例边界。

为什么 planner 自己会剪枝，GSC 仍然有意义？

  • planner preprocessing 是问题构建之后的算法优化；GSC 是进入 planner 之前的治理决策；
  • GSC 记录 rejected action 的原因与 snapshot provenance；
  • GSC 可以编码 availability / safety / authorization，而这些不一定等同于 goal relevance；
  • GSC 的输出是 semantic layer 与 planning layer 之间可审计的 contract，不依赖 planner heuristic。

最危险的问题
Fast Downward 自己会剪掉同类无关结构，GSC 是否冗余？
结论：不冗余，但贡献必须定位为 planner 之前的 governance/admission contract，而非 search pruning 本身。
Oracle 边界
Python/JavaScript 是 cross-implementation independence，不是独立政策真值。
Semantic externality 来自 public PDDL facts/goals。
External selectivity
16/181 provider-related objects 被排除（8.84%）；58/58 rovers 均 admitted。
E6b 强在 no-loss external validity，不是 high-selectivity stress。

Novelty hard-stop

2026-10-08 的最新 prior-art 快速复核未发现同时完成“mission-conditioned heterogeneous Provider–Action domain synthesis + domain membership direct evaluation + same-cardinality controls + held-out native-semantic planner/validator gate”的已有工作。Novelty framing 因此冻结，但仍禁止声称 ontology–planning integration、generic admission 或 freshness checking 本身为首创。
