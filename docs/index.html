Governed Semantic Compilation

系统“知道”一个能力或动作，并不意味着它此刻就应该进入规划器。GSC 研究的是规划前的治理边界：根据当前任务、provider 状态、安全/授权条件和版本化快照，生成本次任务真正可进入搜索的 Provider–Action 域。

90 秒理解

问题知道 ≠ 可执行知识库可以长期保存很多能力，但当前任务只应使用状态、规则和授权允许的那一部分。
方法先编译，再规划GSC 先生成“本任务当前 admissible 的动作域”，规划器再在这个域中搜索。
当前证据机制成立受控实验、跨配置实验与公共规划拓扑均支持该机制；最终独立 planner/validator gate 正在 GitHub Actions 执行。

直观比喻

把 persistent semantic model 想成大型工具仓库。普通做法把大量工具都交给规划器；GSC 先根据今天的任务、哪些工具可用、哪些规则有效、谁有权限，整理出一只任务工具箱，并记录为什么其他工具被排除。研究验证的是：这只工具箱能否既不漏掉任务需要的工具，又减少无效或不合规的选择。

证据边界

现在可以支持

Provider–Action domain membership 是可独立治理和测试的对象；在当前受控与公共拓扑实验中，语义一致 admission 能减少 invalid/distracting alternatives，同时保存任务相关结构。

现在不能支持

“任何 planner 都更快”、真实战场安全有效、任意领域直接迁移、当前 freshness 最优，以及在 gate_summary 真正产生前宣称 E6b PASS。

最重要限制

全部完成证据仍是 software/formal-model/parameterized synthetic；E6b native PDDL predicates 是外部可执行语义，但不是外部人类编写的 binary safety-policy labels。
